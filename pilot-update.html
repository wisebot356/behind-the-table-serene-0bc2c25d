The remaining work

Six pieces before a test link goes out.

  1. Agree on one pilot version

    Reconcile the result drafts and resource names with the repaired routing reference. Replace old September wording and unfinished copy placeholders. Keep the eight approved questions intact.

    Done when: each route has one consistent explanation, a useful action, and a matching resource.

  2. Build the separate test form

    Build Form A with the questions, conditional Q7b, five results, and language that fits owners, employees, and people starting or returning. Do not alter the existing live form.

    Done when: the full experience works on a phone and displays the result without requiring a name or email. A shareable test URL may be unlisted rather than truly private; verify access controls before collecting answers.

  3. Make every promise deliverable

    Prepare a short practical resource for each route. Recommended pilot approach: direct downloads, without automated email. If we offer emailed resources or invitations, build and test a separate optional contact/consent Form B.

    Done when: every resource button works; nothing enrolls a therapist in follow-up by default. The resource content is still needed even if email is omitted.

  4. Set the data-handling rules

    Name the response owner, access list, storage location, retention/deletion date, withdrawal cutoff, and deletion contact. Keep unnecessary integrations off. Collect no patient, claim, payer-rate, contract, or exact financial details.

    Done when: the explanation participants read matches how their answers and notes will actually be handled.

  5. Prove the actual form works

    Check all five outcomes, overload and instability safeguards, Q7b, selection limits, work-setting wording, mobile layout, resource links, and the no-follow-up exit. Compare staged form outputs with the repaired routing reference.

    Done when: no critical routing, privacy, or completion defect remains. Passing Python tests alone is not sufficient.

  6. Prepare the five-person round

    Choose five suitable therapists, a moderator, a short invitation, and a session schedule. Use participant codes in notes and the existing consent, silent timing, and feedback toolkit.

    Done when: Samuel approves the test version, recipients, invitation, and external sharing. No invitations have been sent as part of this update.

Recommended test

Five short conversations, not just five survey links.

Invite warm contacts to an approximately 20-minute feedback session. Start with neutral listening, let them complete the check-in silently on their phones, then ask whether the result fits and offers a useful next move. Test the name, hook, and commercial disclosure if time permits.

Seek a mix of solo practice, payer experience, ownership, newer or returning practice, and outer-island perspectives where feasible. These are useful perspectives, not rigid quotas.

Measure before making a timing promise.

Use “Practice Check-In — pilot” for now. Record actual unassisted completion times and choose an honest public timing claim afterward. Five testers can expose usability and trust problems; they cannot establish statewide demand or scientific validity.

The release gate

“Ready to send” means these checks pass.

  • The approved staging URL works on phones.
  • All five results and key edge cases pass on the actual form.
  • Results appear before any contact request.
  • Promised resources and every exit/request link work.
  • Privacy, access, consent, and deletion rules are set.
  • The invitation, recipients, and moderator are approved.

No launch date is being promised here. Once the decisions above are settled, finish and verify the pilot before booking participant sessions. Wider release requires feedback review, corrections, and separate approval.
